## 1. 背景与目标 / Background & Goal

项目初衷：**一个 app 一体化搞定学校 NAC 网管自助平台的全部常用操作**，不必再开浏览器输地址、在菜单间翻找。

本轮明确的产品形态调整：

- **不强制登录**。对标手机 APP / B 站：导航栏常驻，未登录也能浏览公开页面（概览、状态、设置、关于、日志等只读内容）。
- **操作级按需鉴权**。只有涉及需要身份的动作——上线 / 下线、设备管理、账户资料 / 费用 / 明细查看、改密 / 绑定 MAC——才跳转到登录流程；登录成功后回到原操作。
- 后端把 captive 接入认证（上线 / 保活 / 下线）与自助门户账户管理（资料 / 费用 / 设备 / 明细）两条链路都收敛到 app 内。

## 3. 现状代码诊断 / Current Code Diagnosis

### 3.1 全局强制登录门控（待改造核心）

`qml/Main.qml` 当前用两个 `Loader` 做**二选一**门控：

- `loginLoader.active: !app.session.loggedIn` —— 未登录只挂 `LoginPage`；
- `mainLoader.active: app.session.loggedIn` —— 登录后才加载带 `AppTabBar` 的主框架。

即：未登录时导航栏与主框架根本不实例化。这与"导航常驻、按需登录"的目标冲突，是阶段 A 的主要改造点。

### 3.2 后端三条链路现状

| 链路 | 客户端 | 状态 |
|---|---|---|
| captive 接入认证（上线 / 保活 / 下线） | `core/PortalClient.*` | 链路已落地；本轮已修正 Qt6.8.3 不可用的 `setPeerVerifyName` 编译 API；已在线空响应与失败的区分待未认证口复核 |

## 4. 拟改造方案 / Proposed Plan（分阶段，待确认）

### 阶段 A — 导航常驻 + 页面级按需鉴权（UI，对应任务 #52）

1. 应用启动即进入主框架与常驻导航栏，不再被登录页整体覆盖。
2. 把页面 / 操作分为两类：
   - **公开只读**：概览与在线状态、本机网络信息、设置、日志、诊断、关于；未登录可浏览，数据缺失时展示占位与引导。
   - **受保护**：上线 / 下线、在线与绑定设备管理、账户资料 / 余额 / 费用 / 上网明细、修改密码、绑定 / 解绑 MAC。
3. 未登录触发受保护操作时，弹出登录卡片或跳转登录页；登录成功后回到原操作现场；取消则留在当前公开页。
4. 会话模型区分两类：**captive 在线会话**（是否已入网）与**自助门户会话**（是否已登录 Web 台），各自独立标记、独立登出，避免互相误判。
5. 未登录时不主动发送受保护请求，避免无会话 302 / 空响应刷屏。

### 阶段 B — 后端链路复核与接入（对应任务 #50、#54）

1. 在直连网段复核 captive 上线 / 下线真实报文：成功、已在线空响应、口令错误、验证码缺失、超时 / 403 / 证书异常各分支的判定文案。
2. ~~将 `AccountPortalClient` 经薄封装控制器接入 `AppController`（对称现有 `DeviceController` 模式）~~ **控制器接入已完成（2026-11-23）**：`AccountController` 已装配并暴露 `app.account`；PC 自助页面在导航中归位与 QML 展示仍待登录样本。
3. 取得登录后主页样本后，实现 `parseProfile`：资料、余额、费用、已申请服务、在线 / 历史 / 绑定设备的标签—值解析；字段缺失容错降级。
4. 会话 Cookie / ViewState 生命周期与刷新策略对齐 JSF / ICEfaces 有状态特性。

## 7. 风险与边界 / Risks & Boundaries

- **图形验证码**：PC / 移动自助登录均带 4 位图形验证码；app 不做 OCR 破解，由弹窗展示验证码图、本人手动输入。
- **不越权**：不访问管理员后台、不查询 / 展示他人设备、不批量踢线、不绕过多端限制。
- **老框架兼容**：门户为 PrimeFaces 3.5 / JSF / ICEfaces，在新版浏览器兼容较差；DOM 解析以登录后真实样本为准，不凭猜测写选择器。
- **敏感信息**：口令、Cookie、token、MAC、IP、余额等在日志 / 崩溃上报 / 仓库文案一律脱敏。
- **编码**：POST 表单编码按高级设置（ASCII / GBK / UTF-8），不自动猜测学校平台编码。
