# gdei-connect 界面设计与开发约束

## 1. 项目背景

gdei-connect 是面向广东第二师范学院的校园网客户端，技术栈为 C++17、Qt6、QML、Qt Network，单仓库跨平台构建。

本文档基于当前首页两张预览界面的问题盘点整理，明确界面与交互上**应该做什么、不应该做什么**。

### 1.1 预览界面现状

- **图 A · 首页状态主卡片**：大圆形在线状态区（绿色，标注「在线 / 保活中」）、红色「下线」按钮、「默认配置」卡片及右上角三点菜单、保活说明文案。
- **图 B · 首页网络信息卡片**：本机 IP、目标 IP、子网状态、目标 MAC、网络接口名称、刷新按钮。

### 1.2 实测网络环境

本机处于二级 NAT 之后：

- 本机网卡地址：`192.168.0.0/24` 段；
- 校园网认证出口：`10.0.0.0/8` 段及学校公网段（如 `210.38.64.39`）。

该环境会放大界面中状态混淆、IP 误读、信息拥挤等问题。

## 2. 问题清单

| 编号 | 问题 | 根因 | 影响 |
| ---- | ---- | ---- | ---- |
| P1 | 字体未内嵌，跨平台依赖系统字体 | 未指定字体回退链，未打包中文字体资源 | Linux、安卓精简系统出现方框；不同系统中文粗细、字宽不一致；叠加 GBK 编码时易乱码 |
| P2 | 文本编码未在渲染前统一 | 门户返回内容未做编码嗅探，直接送入控件 | 老门户 GBK 页面转换失败时界面直接乱码，无兜底 |
| P3 | 「保活中 / 在线」与「账号：不可用」同时出现 | 网络连通状态与账号会话状态混在一张卡片计算、渲染 | 用户无法判断是否登录、能否上网，状态自相矛盾 |
| P4 | 「下线」按钮语义不清 | 未区分「停止保活轮询」与「向网关主动登出」 | 易误操作；红色警示样式放在核心状态卡下方风险高 |
| P5 | 本机网卡 IP 被当作校园网 IP 展示 | 未区分本地局域网 IP 与校园认证出口 IP | 二级 NAT 下学生看到 `192.168.x.x`，误以为认证失败 |
| P6 | 子网同/不同子网状态对普通用户无意义 | 底层调试结论直接抬到概览页 | 学生看不懂，且易被误读成故障告警 |
| P7 | 目标 MAC 显示「未提供」文案生硬 | NAT 环境本就拿不到对端 MAC，未做场景化说明 | 用户困惑，分不清是软件故障还是环境如此 |
| P8 | 接口名 `ethernet_32769` 直接展示 | 读取底层内核标识，未映射友好网卡名 | 普通学生无法理解字段含义 |
| P9 | 缺少中间告警状态色 | 只有绿色正常、红色异常，无半残、探测中状态 | 无法表达「DNS 通、TCP 大包丢包、极慢」的半连通故障 |
| P10 | 概览页缺少诊断入口 | 网络信息卡只有刷新按钮，无连通测试、无诊断跳转 | 用户发现网慢、异常时找不到自助排查路径 |
| P11 | 信息排版拥挤、无自适应 | 卡片固定堆叠，未做流式布局与 DPI 字号缩放 | 安卓竖屏、小屏、高 DPI 下文字溢出或挤压 |
| P12 | 图标风格不统一，无加载反馈 | 闪电、WiFi、电源图标风格混用；探测刷新时无骨架屏 | 视觉质感不一致，操作过程空白无反馈 |
| P13 | 状态文案写死 | 文案固定为「自动检查连接，离线时重新认证」 | 无法区分「保活开启但账号已被踢」「保活开启但网络半残」 |
| P14 | 异常事件无轻量提示 | 概览页不展示最近断网、告警事件 | 掉线或探测异常时，必须翻到诊断页才看得到 |
| P15 | 仅深色主题，未预留浅色 | 主题未做结构化分层 | 跨平台用户偏好不同，后续改造成本高 |

## 3. 应该做

### 3.1 字体与编码

1. 内嵌开源中文字体（如 Noto Sans SC，可商用无版权）作为 QML 资源打进程序，全局指定字体回退链：优先内置字体，其次同语言系统字体，最后通用回退。
2. 字号跟随 DPI 响应式缩放，禁止写死像素字号；间距随屏幕密度、窗口宽度自动调整。
3. 编码统一在数据层完成：门户返回文本先做编码嗅探（UTF-8、ASCII、GBK 等），统一转 UTF-8 后再进入 UI 渲染层；原始编码内容不得直接交给控件。
4. 诊断页保留编码调试入口，展示当前探测到的门户编码与转换结果，便于门户改版后排查乱码。

### 3.2 状态体系拆分

状态拆成三个独立数据源，独立计算、独立渲染：

| 状态层 | 含义 | 判定依据 |
| ---- | ---- | ---- |
| 网卡层 | 本机网卡是否存在、是否拿到局域网 IP | 读取本机网卡信息，与校园认证无关 |
| 会话层 | 校园网账号是否登录有效，是否被踢、密码错误、设备超限 | 请求 `nac.gdei.edu.cn:8080` 自助门户会话接口 |
| 探测层 | 外网是否可达、是否半连通 | 短超时 TCP / HTTP 探测，区分正常、半残、离线 |

- 概览页分别展示三层结果，禁止出现「在线保活 + 账号不可用」这类矛盾组合。
- 状态说明文案由探测结果动态生成，不得写死固定一句话。

### 3.3 操作按钮语义拆分

1. **保活总开关**：只控制后台轮询与自动重试是否开启，不向网关发送登出请求。
2. **登出账号按钮**：调用门户下线接口，主动向校园网关登出，需二次确认。
3. 二者 UI 分离：开关走开关样式，登出走按钮样式；红色警示色只用于登出等危险操作。

### 3.4 网络信息面板重构

1. IP 强制分组展示：
   - **本机局域网信息**：本机网卡 IP、子网掩码、网关，标注「局域网内网地址，不代表校园网认证地址」。
   - **校园认证出口信息**：认证后学校侧识别到的出口 IP，标注「校园网认证出口 IP」。
   - 禁止把网卡 IP 当作校园网 IP 展示。
2. 底层调试信息默认折叠：子网掩码、子网同/不同子网比对、底层接口名、对端 MAC 收进「查看详情」，概览页只展示核心两个 IP。
3. 场景化文案：NAT 环境下目标 MAC 无法获取时，显示「NAT 路由环境下无法获取」，不得直接显示「未提供」。
4. 友好网卡名：优先读取系统网卡友好名称（如 Realtek PCIe 网卡、Wi‑Fi 6 AX201），底层内核接口标识折叠到详情。
5. 动作按钮区分：
   - 「刷新网卡信息」：重新读取本机网卡与 IP；
   - 「连通测试」：发起外网与门户连通探测；
   - 两个动作不得共用一个刷新按钮。
6. 子网判断仅作调试数据：同/不同子网结果只出现在诊断页，不参与网络好坏、保活状态判定，不在概览页作为告警。

### 3.5 状态色与反馈

1. 状态色规范：
   - 绿色：网络正常、账号会话有效；
   - 琥珀色：半连通告警，如 DNS 通但 TCP 吞吐严重受损；
   - 蓝色：探测中、加载中；
   - 红色：错误、登出、危险操作。
2. 图标统一使用 Material Icons 等矢量图标库，保持线宽、圆角、风格一致。
3. 探测、刷新、拉取设备列表时显示骨架屏或加载动画，禁止空白等待。
4. 概览页展示最近一条网络告警或断网事件，有未读异常时在 Tab 或卡片上给出红点提示。
5. 主题色、背景色、卡片底色抽成主题 token，预留浅色与深色切换能力。

### 3.6 布局与导航

1. 流式自适应布局：安卓竖屏自动折叠模块，Windows / macOS 横屏自动铺开；高 DPI 与小屏均不得溢出。
2. Tab 命名：
   - 概览；
   - 设备管理（原「设备」，对应自助门户在线设备列表）；
   - 仪表盘（原「我的」，放账号信息、套餐流量、在线时长）。
3. 概览页增加诊断入口，提供「快速连通测试」「进入网络诊断」跳转按钮。

### 3.7 诊断页工具集

诊断页工具全部异步执行，结果写入全局日志队列：

1. 多维度连通性探测：DNS、DoH、DoT、TCP 握手、HTTP 短请求并行探测，识别半连通状态。
2. 网卡信息识别：型号、MAC、驱动版本，命中 AX201 等高频故障网卡时弹出对应指引。
3. TCP 卸载一键检测与修复（仅 Windows）：检测 Chimney、RSS、自动调谐状态，一键执行修复命令。
4. DNS 对比测试：校园内网 DNS 与公共 DNS `223.5.5.5` 并行比对解析延迟。
5. 路由追踪（tracert / mtr）：可视化节点与丢包位置。
6. LibreSpeed 测速客户端：对接自建测速节点，测上下行、延迟、抖动。
7. 日志导出：一键导出网络事件与认证日志。
8. 编码探测：识别门户页面编码并展示转换结果。

## 4. 不应该做

### 4.1 状态与判定

1. 禁止只用 DNS 解析成功判定在线。存在「DNS 通、TCP 半残」的真实故障，必须用短超时 TCP / HTTP 应用层探测判定。
2. 禁止把子网同/不同子网当作网络好坏依据。二级 NAT、宿舍路由器场景普遍，子网比对结果仅作调试数据。
3. 禁止将网卡层、会话层、探测层状态混算或混渲染。
4. 禁止状态文案写死，文案必须随当前探测结果动态生成。

### 4.2 信息展示

5. 禁止把本机局域网 IP 当作校园网 IP 展示。
6. 禁止在概览页默认堆砌底层调试字段：内核接口名、原始 MAC、子网比对结果等。
7. 禁止用「未提供」这类生硬文案描述 NAT 下无法获取的字段。
8. 禁止共用一个按钮执行「读网卡信息」和「网络连通探测」两种动作。

### 4.3 字体、编码与跨平台

9. 禁止依赖系统默认中文字体而不打包字体资源。
10. 禁止把未做编码转换的门户原始文本直接交给 UI 控件渲染。
11. 禁止写死像素字号与固定布局，不做 DPI 与屏幕尺寸自适应。

### 4.4 合规与功能边界

12. 禁止完整 HTTPS 抓包解密、全量流量抓包；仅保留认证相关请求的调试预览。
13. 禁止端口扫描、ARP 扫描、子网扫描等易被校园网判定为攻击的行为。
14. 禁止任何代理、翻墙相关功能。
15. 禁止引入与校园网认证、设备管理、故障诊断无关的工具。
16. 禁止擅自新增需求清单之外的页面与功能。
17. C++ 核心逻辑与 QML 界面严格分层，UI 改动不得破坏认证、网络探测核心业务。

### 4.5 操作风险

18. 禁止将「停止保活」与「主动登出」合并成一个按钮。
19. 登出、踢设备等破坏性操作必须二次确认，默认不允许误踢本机。

## 5. 验收清单

- [ ] 内置中文字体资源，QML 字体回退链生效；跨平台无方框、无字体粗细错乱。
- [ ] 门户返回文本经编码嗅探并统一转 UTF-8 后才进入 UI。
- [ ] 网卡层、会话层、探测层三状态独立展示，无矛盾组合。
- [ ] 保活开关与登出按钮分离，登出带二次确认。
- [ ] 网络信息分「本机局域网」「校园认证出口」两组，底层字段折叠到详情。
- [ ] NAT 下无法获取 MAC 的文案为场景化说明；网卡名显示友好名称。
- [ ] 概览页有连通测试与诊断跳转入口；Tab 为概览、设备管理、仪表盘。
- [ ] 状态色覆盖正常、半残告警、探测中、错误四态；有加载动画与异常红点提示。
- [ ] 布局流式自适应，竖屏折叠、横屏铺开，高 DPI 不溢出。
- [ ] 诊断页工具集可用，日志可导出。
- [ ] 无抓包解密、扫描、代理翻墙等越界功能。

## 6. 附录

- 校园门户：`http://nac.gdei.edu.cn:8080/selfservice/index.xhtml`。未认证时外网被拦截，无 HTTP 劫持自动弹窗。
- 典型兼容故障：Dell Inspiron 7510（Intel AX201）校园网半连通异常。DNS、DoH 正常，HTTP 可加载但极慢，ping 与 tracert 第一跳超时；根因为网卡 LSO、校验和卸载与校园交换机 / 网关不兼容。
- 探测要求：短超时 TCP 应用层探测加超时阈值，禁止只 ping、只查 DNS。
