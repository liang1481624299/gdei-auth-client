0. 审计结论摘要

经过上一轮按报告修复与日志清零后，本轮以当前实际代码重新执行四组并行扫描。整体架构仍保持分层清晰（core 未反向依赖、QML 无文件/网络 IO、悬空调用为空集、i18n 缺失 key 为 0），但 修复动作本身引入了 3 项 P0 回归，且 i18n 双语串与 Android 明文两大历史顽疾仍未根治。

正向结论：① 悬空请求 = 0；② 缺失 i18n key = 0（860 词条四语种齐全，新增 8 条均 4 份）；③ core 无逆向依赖，QML 无业务事件生成；④ 保活状态机、probe 去重、URL 白名单 setter、save 返回值等核心修复确认生效；⑤ 工作区与 TEMP 日志文件已全部清零（29 个）。
最高风险：V-01（i18n key 直达 UI）、V-02（Android 探测被 NSC 拦截致保活失效）、V-03（自助门户明文口令+脱敏漏字段）。三项均为本轮修复直接或间接引入/暴露，建议优先处理。

关键发现

  • 悬空调用：0。全部 app.xxx.yyy() 均有 C++ 定义，信号订阅均有对应 signal。
  • 状态分叉：登出失败时 loggedIn 回滚 true 但 auth.online 仍 false（V 系列 P1）；logout 在 busy 时 return 不发信号导致卡死。
