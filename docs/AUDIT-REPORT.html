一、结论摘要

本次审计覆盖 QML 前端、C++ 业务层、网络发包模块、持久化存储、i18n 与主题适配，并完成证书管理、逻辑孤岛、多系统适配、可扩展性四项专项。所有结论均基于仓库源码静态核对，未引入无依据推断。

总体判断

  • 架构清晰 门面控制器 + core 网络/存储/调度分层明确；QML 不直接发起任何网络请求（已核查无 QNetworkAccessManager / XMLHttpRequest / fetch / WorkerScript / LocalStorage）。
  • 安全基线可用 证书默认严格校验，跳过需显式开启并留痕、UI 二次确认；口令在 Win 走 DPAPI、mac 走 Keychain，后备为 PBKDF2 + encrypt-then-MAC 加密；日志敏感字段脱敏。
  • 主要风险集中在 保活重连缺退避/互斥、GBK 响应解码不对称、账户门户解析空占位、8080 明文门户、非桌面平台密钥库强度。
  • 能力缺口 任务书要求的“内置证书管理器模块”当前未实现；账户中心数据链路与部分跨平台能力（托盘、字体）为占位或平台受限。
合规边界：本报告仅评估本机保活、掉线识别、自动重连与证书管理正确性；校园网“最多 3 台设备同时在线、第 4 台接入随机踢人”为服务端规则，报告不含任何规避名额检测、抢占或保名额的方案。

三、网络 & 接口专项（新华三 Portal 认证）

3.1 接口与链路清单

通道端口 / 协议客户端关键步骤
captive 上线 / 下线443 · HTTPS PortalClient GET 入口页（跟随 302 建 Cookie）→ GET 登录页提取 CSRF → POST 表单（userName/userPwd，口令先 Base64；20+ 隐藏域常量）；下线表单凭据置空
设备自助门户8080 · HTTP（ICEfaces） DevicePortalClient 登录页提取 ViewState/ICE 窗口 → 验证码 → 提交 → macList 设备列表解析
账户自助门户8080 · HTTP（PrimeFaces） AccountPortalClient 验证码 → 口令经 SelfServiceCodec 编码提交 → 主页解析 profile/services（当前为空占位，见 P1-3）
外网连通探测HTTP NCSI PortalClient::externalProbeOnline 2xx + 非空体 + NCSI 特征串判定可达；空登录响应无会话 Cookie 时补发一次旁证探测聚合判定

3.2 鉴权流程与返回码处理（已核）

  • 成功判定叠加多条件：HTTP 状态码 + 报文 errorNumber 解析 + 会话 Cookie / 近期外网探测旁证；空 2xx 体由 onEmptyProbeReply 聚合旁证，无旁证不直接判成功。
  • 返回码分支（PortalClient.cpp:298–305）：errorNumber=1 成功；=7 已在线（重复登录，达成在线态）；=8 本就离线 / 会话已释放（下线兼容分支）；其余码落失败，消息取 e_d / errorMessage / 原文。
  • CSRF / Cookie：登录页提取 CSRF；SessionCookieJar 跟随会话 Cookie，门户切换时换新 Jar 丢弃旧会话。
  • 幂等性：KeepAlive::start 幂等（重复调用不重置失败计数、不重复探测，KeepAlive.cpp:36）；登录/下线由 m_busy 在途守卫。

3.3 保活 / 掉线识别 / 重连策略核查

核查项现状（代码位置）结论
探测间隔随机区间 keepaliveMinSec~MaxSec（默认 150–210s），qBound 收敛到 30–600s；回调里调度下一次，避免探测重叠（KeepAlive.cpp:52–63, 74–78）合理 抖动降低限流风险
掉线识别每次探测结果累计连续失败，达阈值（默认 3，边界 1–10）才判掉线；阈值内仅告警（KeepAlive.cpp:88–98）合理 防单次抖动误触发重登
重连触发达阈值后清零计数并 m_portal->login()（KeepAlive.cpp:105–106）缺陷 P1-1 无指数退避 / 无最大重试 / 无并发互斥
在途竞态PortalClient::login 在 m_busy 时静默 return，不发 loginFinished（PortalClient.cpp:324）缺陷 P1-1 重连被吞，无补偿，恢复延迟到下一轮探测
风暴抑制无退避、无熔断、无重登进行中标志；持续掉线时按固定探测周期反复尝试缺陷 P1-1
下线事件识别外网探测 + 会话健康检查 + 网卡可用态三层；事件经 EventBridge 上抛覆盖 半连通判定仍为已知缺口（见附录）

3.4 参数校验与异常捕获

  • 高级设置前端本地草稿 + validate() 双校验（正数 / 最小<最大 / URL 格式，AdvancedSettingsPage.qml:43–52）；后端 ConfigStore setter 再做 clamp / 范围收敛。
  • 网络异常经 reply->error() 与状态码聚合；缺失凭据在登录前拦截（PortalClient.cpp:320–323）。
  • 报文编码风险：三个门户 decodeBody 对 GBK/GB2312 均回退 UTF-8（详见 P1-2）；两套 8080 门户口令编码口径不一致（详见 P2-2）。

四、新华三证书管理器专项评估

核心结论：仓库中不存在独立的证书管理器模块。全仓检索未出现 QSslCertificate / QSslConfiguration / QSslKey / addCaCertificate / setSslConfiguration / caCertificates / QSslSocket；SSL 处理仅集中在 PortalClient 的 sslErrors 回调一处。

4.1 现有 TLS 处理（已核）

能力点现状位置
证书校验默认策略默认严格校验；未开启跳过则不 ignoreSslErrors，握手错误经 reply->error() 上报PortalClient.cpp:33–43
跳过校验开关仅当配置 allowInsecureSsl 为真才 ignoreSslErrors() 并写警告日志留痕；UI 有二次确认PortalClient.cpp:37–42；AdvancedSettingsPage.qml:267,499
主机名校验IP 兜底建连时 setPeerVerifyName 对齐域名校验名；域名直连由 Qt 自然按域名校验PortalClient.cpp:82–87
证书加载 / 解析 / 持久化缺失 无证书对象加载、链解析、用户信任锚持久化—
证书链 / 根证书信任缺失 完全依赖系统默认根证书库，无应用级 CA 注入—
自签 / 内网私有 CA 兼容缺口 无法单张导入信任内网 CA；唯一兼容手段是全局跳过校验（中间人风险）—
过期检测 / 替换 / 缓存缺失 无到期时间读取、无临近过期提醒、无证书缓存与替换流程—
导入 / 导出 / 文件权限缺失 无导入导出界面与存储权限管理—
校验失败降级 / 告警默认失败即中断并上报；跳过开关为全局降级，粒度粗，无按主机/按指纹的精细放行PortalClient.cpp:33–43

4.2 识别到的风险点

  • 内网证书环境只能全局跳过：校园内网若使用私有 CA / 自签证书，应用无法把该 CA 加入信任锚，用户只能开启“跳过证书校验”，使整条 443 链路暴露于中间人攻击。
  • 无证书可见性：不展示对端证书指纹、颁发者、有效期，排障时无法判断是否为证书过期 / 域名不匹配 / 替换。
  • 8080 门户无 TLS 层：设备 / 账户自助门户全程 HTTP 明文（见 P1-4），证书机制对其不适用。

4.3 修复方向（对应 P2-1）

新增 CertificateStore 子模块：解析并持久化用户主动信任的内网 CA（QSslCertificate + QSslConfiguration::addCaCertificate），按主机绑定指纹与有效期、提供到期提醒；全局跳过保留为最后手段并维持强告警。该能力属新增模块，现有网络层骨架不承载证书抽象。

五、后端逻辑孤岛专项

双向对账：① 后端已暴露但 QML 未对接的闲置能力；② QML 发起调用但后端无实现的悬空请求。对账方式：提取后端 Q_INVOKABLE / Q_PROPERTY 清单，与 QML 中 app.<ctrl>.<member> 实际调用集合比对。

5.1 后端已实现 · QML 未对接（闲置能力）

控制器闲置成员性质 / 风险
AccountController services、captchaImage、fetchCaptcha()、loginWithCode()、logout()、clearSession() 整条 PrimeFaces 账户门户登录 / 登出 / 会话清除链路后端已实现，账号页仅用 authenticated / busy / profile / lastMessage / refreshProfile。长期闲置导致版本口径漂移与维护成本（P1-3）
AccountController / AccountPortalClient profile 数据源 parseProfile 为空占位，profile/services 恒空；UI 以“不可用 / 暂未统计”占位兜底，功能空转（P1-3）

EventBus publish() 后端内部发布入口被标为 Q_INVOKABLE，暴露到 QML 形成理论上的越权发事件面，应收回内部（P2-11）

5.2 QML 发起 · 后端无实现（悬空请求）

逐条核对 QML 调用的控制器成员，未发现悬空请求：QML 调用的 login / logout / refreshStatus / startKeepAlive / stopKeepAlive / fetchCaptcha / loginWithCode / refreshDevices / refreshProfile / addProfile / updateProfile / removeProfile / selectProfile / requireLogin / promptLogin / dismissLoginPrompt / signOutLocal / exportLog / clear / setEventPageVisible 等均在后端有对应实现。

  • 事件模型经 app.eventModel 绑定（EventLogPage.qml:89、DashboardPage.qml:267），非 app.events.model，对接正常。
  • 脚本扫描出的 3 个“悬空键”events.source.（动态拼接前缀）、remote.open / settings.save（门禁 actionKey）均非译文键，属误报。

六、编码规范专项

6.1 内存管理与对象树

  • 网络对象 QNetworkAccessManager / SessionCookieJar 以 this 为 parent 纳入 Qt 对象树（PortalClient.cpp:25–27）；QNetworkReply 回调内 deleteLater() 释放。
  • 未发现裸指针泄漏；控制器由 main.cpp 栈上持有、聚合到 AppController，生命周期与应用一致。

6.2 信号槽连接

  • 跨对象状态转发均以函数指针式 connect；EventBus 用 QueuedConnection 投递待发事件（EventBus.cpp:40–41）。
  • 耦合点：EventBridge 槽函数靠匹配英文日志前缀派生事件（EventBridge.cpp:107,112,117），日志文案 / 翻译改动会静默断链（P2-3）。

6.3 CMake / 编译宏 / 跨平台

  • C++20、CMAKE_AUTOMOC/AUTORCC；固定 Qt6 组件 Core/Quick/QuickControls2/Network/Qml/Svg/Core5Compat，Widgets 仅 WIN32（CMakeLists.txt:16–21,222–230）。
  • 平台条件编译：WIN32 接入 TrayController 与 crypt32；APPLE 链接 Security 框架并剥离已移除的 AGL.framework；MSVC 强制 include stdext 兼容头与 /utf-8，MinGW 设输入/执行字符集 UTF-8；Android 包名 / SDK 版本齐备（CMakeLists.txt:120–123,234–261）。
  • 版本号两处一致：CPACK 与 Android versionName 均 0.2.1（CMakeLists.txt:260,311）。

6.4 注释 / 文案 / 硬编码

  • 源码注释中英双语，关键决策与兼容分支均有说明；i18n 四语言各 306 键、差集为 0（详见附录 A）。
  • QML 显示文案均经 app.i18n.text(key)；扫描仅 1 处中文字符串为设备名匹配逻辑（BrandIcon.qml:30），非展示文案。
  • 硬编码颜色集中在 Theme 令牌；组件内仅 Switch.qml 一处 #FFFFFF、黑色阴影与品牌固定色等合理硬编码。

6.5 重复代码与口径一致性

  • 控制器重复：AccountController / DeviceController 的 busy / authenticated / lastMessage / captchaImage 信号转发近乎同构（P2-8）。
  • 门户客户端重复：decodeBody、enc 百分号编码、状态置位 / 消息设置在三个门户客户端各写一份（P2-8）。
  • 编码口径：两套 8080 门户口令处理不一致（P2-2）；写侧表单编码支持 GBK，读侧解码未跟上（P1-2）。

6.6 跨层 / 非法依赖校验

  • 未发现 QML 跨层直连 core / 存储 / 网络；未发现非法跨域资源获取（QML 内 http(s):// 仅出现在 SVG 的 XML 命名空间声明，非真实请求）。
  • 唯一分层瑕疵为 QML 直写 app.config.*（15 处，P2-7），属视图越权触碰持久化模型，当前由 setter 校验兜底。

七、UI、主题样式 & 多系统适配专项

7.1 主题统一性

  • 色板 / 字号 / 间距 / 圆角 / 状态色全部集中在 Theme.qml：深 / 浅双态，状态色 green/orange/red/blue/gray 深色态同色相提亮；字号阶梯 11→34、间距 4→32、圆角 8→16 + 胶囊。
  • 未发现样式多处重复定义或互相覆盖；组件统一引用 th.* 令牌。
  • 图标经 Icon 组件 IconImage.color 着色，跟随主题 th.text，避免暗色态深色图标不可见（Icon.qml:11,25）。

7.2 布局 / DPI / 高分屏

  • 缩放体系：uiScale = fontScale × userScale × screenScale，收敛 0.8–2.2；dp() 把设计像素映射到逻辑像素；字号跟随系统字体并限制 0.9–1.75（Theme.qml:85–102）。
  • 断点：compactBreakpoint 600、wideBreakpoint 960；页面内容宽屏居中、contentMaxWidth 受限（PageScaffold.qml:14,19,70–71）。
  • 窗口默认 400×720 竖屏，最小 320×480 并与屏幕可用尺寸取小（Main.qml:15–23）；水平滚动条关闭、垂直按需。

8.1 综合评分

  • 优点：UI 与业务经门面解耦；网络客户端、存储、调度、i18n、日志各自独立；新增门户类型可在 core 内平行扩展；配置 / 文案外置。
